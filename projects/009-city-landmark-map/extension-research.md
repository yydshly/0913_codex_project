# 009 · 当前能力总结、旅游理解图研究与场景扩展

> **目标校正（2026-09-14）**：主要交付物是城市与周边的宏观旅游理解图片；真实地图仅作地点细节查询。前一版地图入口的主次关系有误，不能当作生图目标完成。详见[技能目标](skill-objective.md)。

**最新产品要求：**最终要呈现原始参考图那样的微缩城市插画，坐标关系图只作校验依据。构图应以用户能识别的核心标志组织阅读，例如火车站。西安试点选“西安站”为抵达参照、“钟楼”为城区参照，先解释用户与城市的关系，再展开片区；明确区分西安站与西安北站。参考点可以视觉突出，地理位置不能随意移动。相同方法可扩展到机场抵达、酒店周边、校园迎新校门或景区入口，前提是核实所选参照点。生成状态见[西安插画记录](xian-illustration.md)。

研究日期：2026-09-14。状态：已按用户指定新增[西安试点](xian-research.md)，接入 13 个公开地点坐标并绘制两级关系图。路网、路线服务、插画叠加及用户实验尚未完成。下文原始能力分析针对自由构图插画，具体地理实现进度以西安试点为准。

## 一、当前能力：已得到什么，价值到哪里

### 1. 公开 Skill 的本质

找到的 [nano banana 画城市](https://youmind.com/skills/yhbukK6TtKX0t9)由 Shuyi Wang 发布，流程是根据城市搜索资料、组织模板、调用图像模型。已读取公开指令，未运行该服务；与用户截图提到的“老范”版本是否相同仍未确认。

它的直接价值是减少资料整理与提示词填写步骤。没有证据表明它提供独立绘图模型、地理布局算法或导航引擎，也没有对照测试证明比普通提示词更准确、更稳定或更省时。

### 2. 我们当前实际实现

| 能力 | 当前状态与证据 | 可提供的价值 | 边界 |
| :--- | :--- | :--- | :--- |
| 城市视觉表达 | imagegen 生成腾冲、丽江各一张无文字插画 | 快速形成地标、自然景观与城市气质的视觉概览 | 两张固定样例，不是任意城市在线生图 |
| 中文文字分层 | 标题、寄语、六个地标名称由程序排版 | 改字无需重新绘图 | 修改名称不改变景观 |
| 标注布局 | 拖动、滑块、方向键、显隐与编号模式 | 改善阅读、适配版面 | 保存的是画布百分比坐标，不是真实地理坐标 |
| 成品交付 | 三种装裱配色、PNG、JSON 工程、本机草稿 | 支持重复修改与交付 | 不能编辑底图里的单个建筑 |
| 新城市创作说明 | 根据城市、地标和风格输出提示词 | 减少重复组织说明 | 不自动查证输入，不调用在线绘图 |
| 研究可追溯 | 保存来源、完整生成提示词及测试记录 | 区分上游表述、原创实践与事实 | 地标形态、方位和道路未经系统复核 |

已通过 8 项逻辑检查、独立构建和静态引用检查；实际渲染两张 1800 × 2400 海报。底图原生为 1086 × 1448，导出含缩放。没有真实浏览器交互测试或同模型 A/B 评测。

### 3. 当前价值判断

现阶段主要是城市插画与排版流程的实践样例。视觉传播、旅行纪念有应用可能，但技术独特性较弱，商业需求未经验证。

已有的素材来源记录、文字分层、工程保存和导出可以继续复用。整张自由构图插画不宜直接升级成可信的空间地图：给错误布局加上正确地名，仍然会让用户形成错误认识。

## 二、我们的扩展：帮助新人理解一座城市

### 1. 产品任务

面向第一次到访的游客，帮助其回答：

- 城市主要分成哪些区域，各有什么特点？
- 自己住在哪里，机场或车站与主要游览区域是什么关系？
- 景点集中还是分散，哪些适合一起安排？
- 河流、山体、铁路或快速路会怎样影响通行？
- 这一天选择什么范围比较合理，下一步如何进入真正的导航？

目标是先建立空间认识，再支持探索。主张“看图能更快理解和安排行程”属于待验证的产品假设，不能从样图直接推出。

### 2. 与现有选择相比，新增什么

| 现有方式 | 擅长的任务 | 理解图希望补充的任务 |
| :--- | :--- | :--- |
| 普通电子地图 | 查地点、查路、导航 | 用少量区域与精选地点解释整体结构 |
| 文字攻略与景点清单 | 提供内容、经验与主题 | 把地点组织成空间关系和可组合的游览范围 |
| 自由构图城市海报 | 表现特色、引发兴趣 | 让特色表达有可信的位置关系 |
| 自动行程表 | 给出时间顺序 | 解释为什么这样组合，便于用户自己取舍 |

这些是功能定位，不意味着现有地图产品完全没有相关能力。实际优势必须通过与用户当前使用方式的对照验证。

### 3. 两个尺度，避免把城市与远郊挤成一团

第一层是“城市与周边概览”，说明核心片区、交通枢纽及远郊景区的大致关系。第二层是“单个片区展开”，展示步行街巷、入口和几个适合一起探索的点。

初版建议统一采用北向上的概览，使用区域块、主要水系、必要交通连接与地标图标。不要为了容纳远处景点把所有距离挤成看似几分钟可达；需要局部放大时使用明确的插图框，并保留其在总图中的定位。

首个研究城市现按用户要求确定为西安，已围绕钟鼓楼、雁塔一带、临潼与抵达枢纽建立 13 个地点档案；详见[西安数据与地理约束](xian-research.md)。腾冲保留为自由构图插画基线，不作为本轮地理验证城市。

### 4. 哪些可以艺术化，哪些必须受约束

| 对象 | 允许的处理 | 必须保留或说明的关系 |
| :--- | :--- | :--- |
| 建筑 | 放大为可辨认的插画图标 | 地理锚点固定；图标大小不表示建筑真实占地 |
| 区域 | 简化边界，突出旅游主题 | 明确是“旅游理解分区”还是行政区，不混淆 |
| 河流、山体 | 减少细节、调整视觉表现 | 保留影响理解的相对关系；桥梁连接不能虚构 |
| 道路 | 只展示主要连接 | 有真实数据才展示路径；不能让装饰小路暗示可通行 |
| 地标名称 | 可独立排版、避让遮挡 | 名称和地点身份对应；移动文字不移动真实地点 |
| 距离 | 可分层、局部放大 | 标明非等比例区域；不按变形后的图面长度估算车程 |
| 交通时间 | 以清晰的时间范围解释距离感 | 来自路线数据或人工实测，记录方式、查询时间和不确定性 |

编辑器应拆开“地理锚点”和“标签位置”。现有自由拖动只适用于海报；理解图默认只允许移动标签，必要时用引线回指锚点。

### 5. 推荐实现路线：真实结构与插画素材分开

建议初版流程：

1. 选定目标人群与范围，人工核实约 10–15 个地标、3–5 个旅游片区和必要交通枢纽。
2. 为每个地点记录稳定标识、正式名称、经纬度、坐标系、入口位置、资料来源和核实日期。
3. 统一坐标系，按真实坐标投影到画面；用简化数据绘制河流、片区与主要连接。
4. 生成或取得独立地标插画，将其放到对应锚点附近，而非让模型重新决定整个城市布局。
5. 程序独立排版名称、简短区域说明和交通信息，处理遮挡。
6. 点击地标可看“为什么值得去”“和哪个片区有关”；需要出行时跳转外部地图。
7. 导出简版图并标注来源和更新时间；有明显变形的图不显示会误导的统一比例尺。

这一方案的可控性来自地理结构与素材分层，而不是提示词变得更长。

| 技术路线 | 优点 | 核心问题 | 研究选择 |
| :--- | :--- | :--- | :--- |
| 坐标布局＋独立地标插画 | 地点和标签可控，单个素材可替换 | 需要统一视角、处理拥挤和图标归属 | 初版优先 |
| 地图结构图＋整图受控生成 | 视觉更完整，可能保留较多底图特征 | 仍需检查道路、方位与锚点是否漂移 | 作为对照实验 |
| 真实三维场景＋风格化渲染 | 更强的空间和视角控制 | 模型、地形、标注和性能成本更高 | 暂不作为首版 |

ControlNet 论文提供了边缘、深度、分割等空间条件控制方法，因此第二条路线具有研究依据；论文并未证明生成结果满足地图准确性，也不能据此假设当前内置 imagegen 暴露这些控制接口。[论文](https://arxiv.org/abs/2302.05543)

### 6. 可用的数据与组件

| 需要 | 已查阅的官方能力 | 对本项目的含义 |
| :--- | :--- | :--- |
| 地点和坐标 | 高德列出 POI 搜索、地理编码和坐标转换接口 | 西安已人工核对 13 个高德公开地点页坐标；未接入 API 自动查询 |
| 交通关系 | 高德路径规划 2.0 提供驾车、步行、公交等路线服务 | 车程来自算路，不能用直线距离代替；需申请 Key |
| 地图承载 | MapLibre 支持 GeoJSON 地点与 symbol 图层、图标和文字避让设置 | 可作为真实坐标与独立插画组合的渲染候选 |
| 静态底图 | Mapbox Static Images 支持标记、路径、GeoJSON 叠加 | 可作为结构参考或静态输出候选；不自动保证后续生图准确 |
| 开放数据 | OpenStreetMap 提供开放地图数据及署名要求 | 可作候选数据源；覆盖质量、服务使用及具体条款需按用途核实 |
| 导航承接 | 高德 URI 支持起终点与出行方式 | 初版可将导航交给现有地图服务 |

依据：[高德 API 目录](https://developer.amap.com/api/)、[路径规划 2.0](https://developer.amap.com/api/webservice/guide/api/newroute)、[高德导航 URI](https://developer.amap.com/api/uri-api/guide/travel/route)、[MapLibre symbol 图层](https://maplibre.org/maplibre-style-spec/layers/)、[Mapbox Static Images](https://docs.mapbox.com/api/maps/static-images/)、[OpenStreetMap 来源与许可](https://www.openstreetmap.org/copyright)。

工具和数据源是候选，不是全部引入。优先选用一个主要地点 / 路线来源；若混合数据，明确其坐标系与更新时间，避免直接叠加造成偏移。本轮没有申请密钥、调用路线 API 或估算服务费用。

### 7. 最小验证范围

首版只回答“区域怎样分布、主要看什么、哪些适合一起探索”。单城制作两级视图，并保留普通地理结构视图作对照；住宿入口、实时价格、餐厅排名和自动完整行程暂不扩展。

验证分两组：

**地理与内容检查**

- 所有上图地点都有来源、坐标系和核实日期；没有坐标的项目不假装已精确定位。
- 经纬度锚点与显示位置对应，文字移动不改变锚点。
- 抽查河流两岸、关键跨河连接和城市 / 远郊关系。
- 所有“可步行”“约多久”的信息有路线来源、交通方式与时间戳；缺失则明确未知。
- 换一个地标插画时，其他地理结构保持不变。

**新人理解实验**

先招募 8–12 位不熟悉该城市的人做探索性测试；这是计划样本数，不是已完成实验，也不足以证明市场需求。比较普通地图＋同一份精选地点清单与旅游理解图，保持信息量相近，并轮换展示顺序以减少学习效应。

测试任务：指出几个片区之间的关系、选出适合合并游览的地点、识别一组看似近但通行不便的地点、说明住宿点与目标片区的关系。记录正确率、完成时间、错误的距离判断及选择理由。

只有当空间理解或安排效率改善，且不增加误导性判断，才支持继续投入。若只是“更好看、更想分享”，价值仍主要在视觉内容。商业价值另用民宿或旅行服务方的真实使用、修改工时和付费试单验证，不用口头兴趣代替。

## 三、其他可扩展场景

以下优先级是基于任务相似度与数据可得性的研究判断，不是已验证市场排名。

| 场景 | 谁要解决什么问题 | 理解图的具体作用 | 额外数据 / 难点 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| 民宿 / 酒店周边 | 住客首次到店，不知道附近怎样安排 | 以住宿点为中心说明早餐、散步、景点和交通关系 | 真实入口、步行路网、营业信息；按出行时间而不是圆形半径分组 | 高 |
| 景区 / 古镇初访 | 游客面对多个入口和片区 | 解释主入口、核心区域、游览顺序与返回方式 | 管理方底图、步行通道、坡度与临时关闭 | 高 |
| 校园迎新 | 新生、家长和访客初次入校 | 理解校门、宿舍、食堂、教学楼与报到路径 | 校内入口、开放权限、最新报到地点 | 中高 |
| 城市主题探索 | 用户想按建筑、文学、茶咖或工业遗产探索 | 在真实区域中解释主题联系与可组合路线 | 主题内容策划、地点核实和营业更新 | 中高 |
| 新居民生活圈 | 搬到陌生片区，不熟悉日常设施 | 认识买菜、医疗、交通、公园与生活片区 | 服务范围、营业时间、交通条件和持续维护 | 中 |
| 亲子 / 长者出行 | 需要少绕路、适时休息 | 突出厕所、休息点、台阶、遮阴与换乘负担 | 现场设施和路段核实；不能根据距离推断无障碍 | 中，先取得可靠数据 |
| 历史 / 研学地图 | 学习者难理解事件与地点关系 | 将人物、年代与真实地点关联，切换历史与当下 | 历史位置不确定性、年代分层与内容依据 | 中 |
| 展会 / 园区活动 | 短时访客需要理解分区和集合点 | 说明展区、入口、服务设施与活动动线 | 主办方平面图、楼层、实时改动；不适用普通城市路网 | 中低，单独验证 |
| 旅行回顾 | 旅行结束后想整理走过的地方 | 将真实足迹、照片与区域组织成回忆图 | 用户授权的轨迹和照片；偏纪念而非出行决策 | 可复用交付，但用户任务不同 |

### 优先选择的依据

首选“城市初访概览＋民宿周边展开”：前者验证理解价值，后者有明确分发入口和内容维护方。两者能共用地点、片区、插画和版式结构。

景区与校园在得到管理方可靠底图时也适合，边界较清晰。亲子无障碍、室内展会、历史复原各有不同的数据责任，不宜仅更换提示词就作为同一能力上线。

商业交付可研究按地点定制、按内容更新维护或授权使用；暂不定价，不声称已有客户。每单应记录资料核实、素材制作、地图编排、修改和后续更新的工时，判断可否形成稳定交付。

## 研究决策

保留当前版本作为“自由构图城市插画”的基线。009 后续重点转向“有地理依据的城市旅游理解图”，先验证真实结构和新人理解任务，再增加生成自动化与更多场景。

这次完成的是能力总结与扩展研究；地理布局、交通时间、区域分组、独立地标素材和用户实验仍属于待实施项。

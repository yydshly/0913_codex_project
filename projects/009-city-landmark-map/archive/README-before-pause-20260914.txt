## 三部分研究结论

1. **原始能力**：核心为通用模型出图和独立排版，适合城市插画；原始 Skill 未见真实地理处理能力。我们新增的西安坐标关系图为独立实现。
2. **我们提出的扩展**：先确定地理锚点、区域和关键连接，再放置独立地标插画；通过“城市概览＋片区展开”验证新人能否更快理解与安排探索。
3. **其他场景**：优先研究民宿周边、景区初访与校园迎新；主题探索、新居民生活圈、亲子长者出行、历史研学、展会和旅行回顾分别评估所需数据。

[完整能力总结与扩展研究](extension-research.md)包含实现路线、官方数据依据、验证方法和九类场景。[西安试点](xian-research.md)记录当前已实现部分与 13 个地点来源；其余扩展仍为方案。

## 可以直接体验的功能

西安默认页：用户提供的微缩插画，全图/细节查看，保存原图，查看六个核心地点来源，默认选择西安站。地理依据页 geography.html：四种范围、13 个地点的坐标与来源、直线距离比较、SVG 和 JSON 导出。真实路线与交通时间待接入。

插画工作台（studio.html）：

- 切换腾冲、丽江两个城市样例，每个包含六个地标。
- 编辑城市标题、副标题、旅行寄语和地标名称。
- 拖动标注，或使用横向 / 纵向滑块精调；聚焦画布后也可用方向键调整。
- 独立显示或隐藏标注，切换完整名称、仅序号或无标注。
- 切换纸白、松绿、夜墨三种装裱配色；配色不会重画插画。
- 导出 1800 × 2400 PNG；保存和导入 JSON 工程；各城市草稿自动保存在本机。
- 为其他城市编写绘图提示词，并复制或下载。此操作只整理创作说明，不调用在线生图。

隐藏标注不会移除底图上的建筑；编辑地名不会重画该地标。当前样例不是实时生成，不支持任意城市一键在线出图、路线规划或真实 3D 漫游。

## 本地运行

需要 Node.js 20 或更新版本。本次验证使用 v22.15.0，无需安装依赖。

在仓库根目录执行：

~~~powershell
node projects/009-city-landmark-map/app/serve.mjs
~~~

打开 [本地工作台](http://127.0.0.1:4309/)。这是仅在服务运行时可用的本机地址，不是已部署网址。

~~~powershell
node --test projects/009-city-landmark-map/app/studio.test.mjs
node projects/009-city-landmark-map/app/build.mjs
~~~

构建输出在 app/dist/，可由仓库既有构建脚本汇总到 site/；本轮未修改发布流程或提交其他项目。

## 原始方法研究

已读取公开 Skill 的完整指令：先搜索用户指定城市的资料，补全城市、地标、自然环境等模板字段，然后调用图像模型。页面没有提供地图坐标处理、可编辑图层、路径规划或 3D 渲染代码。它更接近特定任务的创作流程，而不是独立绘图模型或地图引擎。

这能解释“少量输入得到丰富视觉结果”的体验，但不能证明自动选材准确、跨城市稳定或节省了多少成本。不能用本项目的独立样例证明原始 Skill 的增益。

## 实际观察与限制

两张生成图均覆盖了要求的六类景物，没有可见标题或标签，适合后期排字。腾冲文笔塔的层数与比例未精确还原；丽江雪峰、古城和木府按艺术构图重排。地标名称与归属已查阅政府资料，具体外形和空间关系未逐项核实。

更适合城市印象、旅行纪念和文旅视觉素材。用于民宿周边导览时，须另核实位置与路线；是否付费、修改成本和商业收益尚未验证。

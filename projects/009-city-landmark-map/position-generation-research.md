**后续校正**：用户要求位置自动校验，人工观察表不再是默认路径。本文件保留首轮实验过程；当前实现与能力边界以[受控合成自动校验研究](automatic-position-audit.md)为准。

研究日期：2026-09-14。目标是生成原参考图那样的景区微缩插画，只关心大体位置、景观身份、名称与短看点。首页已接入最新用户样图；本研究底稿仅是内部生成依据。

## 一、如何确定位置

### 地点身份先于坐标

每个地点保留唯一 ID、全名、地区、坐标来源、核对日期、坐标体系、点位含义与景观资料来源。场馆中心、办公地址、景区入口、同名商业门店不能互换。具体入口仅在会改变图上区域归属时影响本任务，不扩展到导航研究。

当前8点：钟楼、大雁塔、大明宫、汉阳陵、华清宫、兵马俑、翠华山、古楼观。复用 atlas-data.mjs 中已记录的高德 GCJ-02 参考点和来源，原型不重新假造坐标。8点只用于验证方法，不是最终收录配额；朱雀、动物园、袁家村、白鹿原等仍在完整候选池中。

“古楼观”本轮具体对应已保存的北门参考点，不能自动等同用户图中含混的“楼观台”全部景区。山岳的一个参考点也不代表整个山体范围。

### 坐标与投影

[GeoJSON RFC 7946](https://www.rfc-editor.org/rfc/rfc7946#section-4)使用 WGS 84，并按经度、纬度顺序表达位置；所以原始 GCJ-02 不能直接伪装成该规范的 GeoJSON。本原型使用自定义布局 JSON，完整保留坐标体系，不导出假 GeoJSON。

项目已有 [coordtransform](https://github.com/wandergis/coordtransform) 2.1.2（MIT）用于地点地图的 GCJ-02/WGS-84 近似转换。研究底稿全部使用同一 GCJ-02 数据，混入其他体系会拒绝；坐标转换不是实地测量证明。

本原型复用 xian-geo.mjs 的局部投影：经度差乘平均纬度余弦，纬度差直接换算，最终统一缩放。范围限制为经纬跨度均不超过3度、纬度绝对值不超过80度；这些是原型保护界限，不是精度达标标准。当前没有量化投影误差，不能据此宣称米级准确。

陌生或范围更大的城市应先选择合适投影。可比较 [PROJ 的方位等距投影](https://proj.org/en/stable/operations/projections/aeqd.html)，但不能声称本次已经采用该库或验证其在所有城市的效果。

### 允许艺术化的边界

真实点位与排版位置分开保存。移动地名牌可以用引线关联，不能用地名牌坐标代替景观落点。原型只做统一缩放；后续任何距离压缩都必须显式记录变换和再验证关系，不能在图片里任意挪动。

密集城区有三种待比较方式：扩大整幅画布、设置明确边界的城区放大区域、在方位约束下优化景观占位。不能通过只缩小允许误差圆来解决素材重叠。

## 二、如何确定效果

风格参考是用户原始腾冲／丽江图及最新西安样图中有效的视觉特征：高俯视、微缩质感、独立景区、稀疏背景。最新西安样图不作为地理依据，也不自动作为每个景区建筑外形依据。

每处景区另外准备简短资料包：代表特征、可追溯的实景参考链接、不可混淆对象、一句看点。建筑身份审核采用场馆或运营方资料，不能用另一张 AI 图证明真实形态。图片使用权限另记录；不默认把网上照片下载再上传。

| 比较项 | A：整图图生图 | B：分景区生成、代码合成 |
| --- | --- | --- |
| 生成输入 | 相同位置底稿＋风格参考＋景区资料 | 相同资料，分别制作景区素材 |
| 位置控制 | 模型可能偏离底稿，需观察实际落点 | 素材绑定 ID 和本地落点，再由代码放置 |
| 视觉优势假设 | 背景和光照较易统一 | 每处可单独修改，名称不受生成影响 |
| 主要风险 | 漂移、漏画、景观与标签不一致 | 拼贴感、边缘接缝、素材遮挡、外形不一致 |
| 当前证据 | 未进行本底稿的有效生成 | 未进行分景区素材生成与合成 |

B 的素材本地落点要在景观接地基部选取，而不是默认整张素材中心；代码放对矩形不等于画面中的建筑站对位置。对透明留白、接地位置与遮挡应另外检查。整图最终润色可能改动已经固定的景观，因此润色后必须重新观察和验收。

## 三、准确校验如何执行

### 分开保存三份材料

1. 真实地点依据：坐标、身份、来源。
2. 计划布局：投影结果、景观落点允许区域、地点关系。
3. 成图观察：真实成图哈希和尺寸、实际景观落点、身份核对来源及说明。

计划布局不能复制成观察记录。无成图、无法定位景物或身份无法确认时保持 pending；确认漏画、重复、错位或身份错误时判 failed。位置通过也不代表美学通过。

### 已实现的检查

position-study.mjs 为每对位置在 x/y 轴上差异至少12像素的点生成顺序约束。12像素是1400×900实验画幅的死区，避免把近似同经纬线关系当作硬性方位；它不是行业标准。允许落点半径取34像素和最近邻距离的35%中较小者，目的是先隔离邻近地点，正式阈值要由画幅和示例校准。

验证器检查：独立观察类型、成图哈希字段、画布尺寸、每点是否观察、重复／未知 ID、明确漏画、落点偏离、关键顺序倒置、身份审核状态和来源。verify-artwork.mjs 进一步读取实际 PNG 的尺寸与 SHA-256，防止把旧图观察直接用于新图；哈希只能绑定文件，不能证明观察判断正确。

当前输入落点是人工或后续视觉工具的观察结果。代码没有读取像素识别景区；OCR、地标检测和视觉模型尚未接入。自动视觉识别未来只能作为候选观察，低置信度必须待核，不能由模型自评给出真实性保证。未知对象仅在观察者记录其 ID 后可发现，不代表程序自动看出了所有虚构景物。

### 尚未实现的检查

完整标签 OCR 与对应关系、实际景观边界／遮挡、重复景观的像素检测、建筑细部真实性、近中远等级独立检测、跨区域放大图的尺度校验。当前位置允许区域与顺序检查不替代这些项目。原型的 passed 仅指观察数据满足已实现规则，不代表生产成品合格。

## 四、运行与复现

在 app 目录：

```powershell
npm run research
npm test
npm run build
npm run check
node verify-artwork.mjs ../assets/xian-position-plan.json 实际成图观察.json 实际成图.png 报告.json
```

研究导出保存 SVG、布局 JSON、空观察模板及初始报告；网页 research.html 另提供 PNG 导出。成图观察的坐标单位为布局画框像素，必须与1400×900画框一致；如模型返回其他尺寸，需先确认没有裁切或新增边框，再明确换算／配准，不可只改 JSON 的宽高。

命令行校验只有规则通过才返回0，失败或待核返回2。不要拿空模板作为已完成观察。新增的测试使用合成观察作为故障注入，不是真实图像的视觉评测。

## 五、下一阶段的具体交付

1. 补核用户明确要求景区的坐标与景观特征；新增点保留资料缺口。
2. 解决4组密集点的占位问题，输出可实际放入景观的布局版本；选定后冻结布局版本。
3. 对同一底稿做 A/B 出图，保存实际工具、提示词和结果，不以生成失败记录充当比较结果。
4. 在真实成图中标注景观落点，运行校验；同时人工审核景观身份与整体自然程度。
5. 按实验证据选择工作流，再决定是否把脚本搬入独立 Skill。目前仍为项目内研究 Skill，未全局安装。

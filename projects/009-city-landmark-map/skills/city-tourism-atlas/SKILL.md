# 城市微缩旅游图鉴

产品目标面向全球任意地点输入；西安是首个验证样本，不是固定城市模板。执行位置驱动生成或陌生城市任务时，先读[西安产品验证基线](../../xian-product-validation.md)：区分地点来源证据、布局合成位置和真实外形三层状态。不能把同源多个网址计为独立坐标证据，不把已实现的字段检查当作自动事实核实。城市参照、覆盖名单与阈值放入任务配置；缺少事实时保留待核，不随机补点。

主要产物是类似原始参考的景区微缩总览插画：有价值的景区、可辨识的代表景观、名称和简短看点，保留真实大体方位。当前西安任务不深入街巷、小店、路线和营业细节；这些只作为其他任务的候选扩展。城市或车站作小型方向参照，景区是视觉主体。位置底稿属于内部生成依据，不能替代效果图；地图用于地点详情。

## 内容审查先于生图

按用户需要的主题筛选有意义的景区及游览目的地，涵盖历史景观、山林、动物园、园林和民俗村落等实际类型，不强行凑配额。研究口碑时保留证据，不凭热度或容易绘画决定收录；用户只要景区总览时不自动扩展到全部城市生活细节。

为候选地点写出：它是什么、具体能看或做什么、对谁有意义、为何值得纳入、支持这一判断的资料、空间范围及尚待核实的内容。当地人的使用证据与游客热度分开记录；官方宣传、个别采访或作者建议不能包装成全体本地人的偏好。

在制定完整生成稿前检查重要遗漏。已有地点不能因不够好画或留白不足而默默删除；避免以固定景点数量限制城市内容。内容密度过高时调整画幅、分级标注或增加片区放大插画。主图应让重要片区可发现，放大图承接街巷与具体点位；仍以图片为主要产物。

本轮用户纠正后，西安 V2 的视觉改善仅作为画法经验，原清单不再作为默认完整清单。先读 [内容优先选点规则](references/content-selection.md) 和 [西安内容清单补充研究](../../xian-content-inventory.md)，再决定是否已有足够内容依据进入下一轮生图。

## 区分固定要求与任务输入

固定要求：实际探索价值、重要景区覆盖与最终图像的大体地理正确性共同验收，再检查微缩表达与标签。背景克制不能成为删减有意义地点的理由。

每次确定：城市、覆盖范围、抵达或中心参照、主题与目标读者、画幅、必选地点、风格参考，以及本轮是“交付提示词”还是“生成图片”。从上下文补足能推断的输入；只有影响选址与构图的缺失才需要询问。用户只要提示词时，不额外调用生图或修改应用。

## 地点与地理依据

点位与园区边界使用不同核对方法。参照[西安真实位置证据实验](../../xian-location-evidence.md)，不能把多边形中心伪装为第二独立坐标；统一坐标系、保留原数据和转换路径后检查落点是否在具名边界内。靠近边界时保留不确定性，不能调小缓冲来强行通过；区域支持与精确点位一致性分开报告。原始坐标变化后重新计算证据。当前示例只支持局部简单闭合面，不代表全球复杂地理范围均已支持。

从较完整候选池中识别值得认识的地点及其相互关系，记录收录、合并和暂缓理由，不以“画起来漂亮”取代判断。抵达点与城市中心可以不同。机场航站楼、同名车站、馆区与入口要分清；看点介绍不自动附带实时开放或车程承诺。

使用可追溯来源核对地点身份与方位，保存来源日期和坐标体系。已有同次研究的有效资料可复用。用坐标推导简短的相对位置约束；不要期待将坐标塞进提示词就能保证模型精确绘制。未经核实的新增点不写成确定事实。

把关系转成构图不变量：东西南北、城墙内外、山脚与山体、中心与远郊的分隔。允许地标放大和空白距离压缩，但不允许倒置方位、混淆站点或把远郊挤成城内邻居。远目的地使用单独插图或独立画幅时，应说明不同比例。

宏观方位验收应看景点所在区域及其落点，不以地名牌的位置代替真实落点。若画面标北上，东北区域应有清楚的右上关系；立体透视不能成为方向读不清的理由。优先用少量片区位置约束纠正，不增加背景路网。

## 视觉语言

- 高俯视的微缩景观图鉴；尽量无地平线，避免强烈近大远小使远处地标难认。
- 景点建筑、园林与山地形成可独立辨认的景观单元；地标可放大，普通楼房只是少量背景。
- 用简化街区、田野、绿地与纸面留白分隔片区。既保留地域关系，也避免连续住宅楼填满画面。
- 景区是第一阅读层，名称与简短看点辅助阅读；抵达点与城市核心提供方位参照，不占据大部分画面。
- 地名加必要的一句看点；避免长篇说明、装饰性口号和大量同权重文字。
- 普通道路只表达环境，不虚构导航路线；山水按真实区域组织，不为了好看增加大河或山脉。

内容审查后，制定或纠正画风时读 [视觉对照与验收](references/visual-review.md)。[西安 V2 生成稿](references/xian-v2-prompt.md)仅保留为画风实验历史，不能当作内容覆盖已通过的默认模板。

已有候选图通过某些视觉观察项时，保留那些局部效果，只针对已证实的缺陷修订；不能因画风改善而默认其地理、文字和建筑形态全部合格。西安第二张用户样本的具体证据见 [V2 验收与局部修订稿](references/xian-v2-review.md)。

## 交付模式

**提示词模式**：交付一份完整可复制的生成稿，将主要画风与构图放在前面，随后列地点关系、精简文字和关键禁项。明确参考图角色；不要把不合格结果当作风格参考。需要对照时说明本轮只改哪些变量。

**图片模式**：使用可用的生图能力；在 Codex 环境优先遵循 imagegen 技能。先查看每张输入图，标明风格参考或修改目标。工具返回后按验收规则检查，再保存图片、实际提示词与来源。失败时如实报告，没有新图就不能用旧图或地图声称交付；不擅自切换付费 API 路径。

图片是主交付物；未经用户要求，不扩展成网站改版或部署任务。需要迭代时针对最重要的已观察缺陷修订，避免不断追加细节把图鉴重新推向全景城市画。

## 验收与记录

接入生成的景区素材时，参考[实际素材集成实验](../../scenic-material-integration.md)。以工具实际返回尺寸和透明边界为准，不假定提示词的分辨率或分格要求已执行；先验证源图及素材绑定，再合成。密集城区可使用明确标注的独立放大区，跨图幅不比较像素距离。当前8处候选素材已完成位置自检，景区外形和连续景观效果尚未验收。

涉及位置准确性、陌生城市或代码底稿时，使用[自动位置校验与受控合成](references/position-verification.md)。当前位置自检采用素材身份绑定、受控合成、最终可见像素归属扫描与输出完整性检查，不依赖人工认识城市或填写观察坐标。旧人工观察模式仅供调试。分别报告位置状态与作品状态：程序自检不能证明上游坐标或素材外形真实；自动语义识别与真实景观融合尚未验证。

采用 [视觉对照与验收](references/visual-review.md) 的地理、文字硬性检查和视觉观察项。真实图片未返回、未检查，或关键地理关系不合格时，不标记为可用成品。提示词结构检查不等于生图效果验证。

记录模型或工具（无法确认则待核实）、日期、输入图来源、许可状态、实际提示词、输出路径、已确认问题与待验证项。用户上传图片单列来源，不冒记为本地工具返回。保留失败记录和版本，不覆盖原参考。

# 为什么水花像弹珠，以及采用什么算法

研究日期：2026-09-14。上游 Eanpa Sky v0.2.1，commit `a197d3dc42577e9b870b471a39d6b1710c5b5633`。问题出在宿主上一轮新增的 `courtyard-rain.js`，不是认定上游全部水花都有同一问题。

## 原因

旧补充水花是 `SphereGeometry(1,5,3)` 缩放至 (0.014, 0.02, 0.014)：实际直径 28 毫米、高度 40 毫米。石面发射速度固定 1.7 米/秒，在重力下理论抬升约 14.7 厘米，另有初始高度偏移。每个落点固定三个同样大小的球，运动方向每周期重复，透明度没有随年龄降低，到 0.23 秒突然消失。球面高光、较大尺寸和整齐上抛一起产生弹珠感。它没有真正做多次碰撞反弹，但视觉上像弹起的固体。

## 本轮采用：落点事件驱动的微小飞溅

- 改成两个三角形组成的透明薄片，朝向镜头；高斯软边，按投影速度拉成长短不一的细小水线。
- 直径设为 1.4–3.2 毫米。为了减少远处闪烁，允许最低像素宽度，同时按真实尺寸 / 显示尺寸降低透明度，避免远处又变成亮白大点。
- 用重力加线性阻力计算短轨迹。位置包含 `(1-exp(-k*t))/k` 的阻力衰减项，重力持续向下；回落到地面即消失，不再反弹。
- 每次事件重新确定速度、方向和出现概率；快速淡入并在短寿命内淡出。对当前参数，石面最大抬升小于 2.4 厘米，泥土小于 3 毫米。
- 泥土减少飞溅，石面保留短促飞溅，浅洼以扩散涟漪为主、少量细滴为辅。已有蓄水与雨停过程保留。

这是适合当前院落展示的工程取舍，不是对真实飞溅实验的拟合。近处水花更新仍由宿主计算、实例化提交，不宣称完整 GPU 流体模拟。

## 可选路线

| 路线 | 适用目标 | 对当前场景的判断 |
| --- | --- | --- |
| 落点事件 + 透明薄片飞溅 + 衰减涟漪 | 普通雨、路面、小水洼 | 本轮采用，容易按材质调整，开销可控 |
| 翻页水花序列图 | 非常近的水冠、复杂破碎形状 | 后续可加入经过授权的真实或离线模拟素材，需要处理角度和光照一致性 |
| 二维水面波动场 | 涟漪互相传播、叠加的连续浅水面 | 适合进一步升级水洼，需要边界、稳定时间步与水面法线重建 |
| 三维流体求解 | 倒水、汇流、大量液体交互 | 对当前雨景成本较高，只有业务需要时再引入 |

参考：[NVIDIA Rain 白皮书](https://developer.download.nvidia.com/SDK/10/direct3d/Source/rain/doc/RainSDKWhitePaper.pdf) 说明粒子展开为薄片及其随视角、光照变化的渲染路线；它研究空中雨丝，并不直接验证本轮落地模型。[GPU Gems 3：实时三维流体](https://developer.nvidia.com/gpugems/gpugems3/part-v-physics-simulation/chapter-30-real-time-simulation-and-rendering-3d-fluids) 展示完整流体模拟的求解与渲染组成。上表选型是针对本项目的判断，并非来源中的性能承诺。


2026-09-14 / 15 更新：二维水面波动场已经接入三处浅洼，采用 CPU 小网格直接更新顶点高度与法线，详见 [完整听雨说明](sensory-experience.md)。没有引入三维流体求解。

## 核心价值：让整个场景共同响应天气

可复用的部分是“时间、天气、风、光照、地表状态、事件”的共同驱动关系。只换一张天空图无法同步实现屋檐遮雨、地面变湿、反射变化及对应声音。

| 层次 | 当前能力与原理 | 接入另一场景需要什么 |
| --- | --- | --- |
| 环境 | 三维密度场沿视线采样形成体积云；太阳时间驱动天空、主光、环境光和云影 | 同一相机、世界方向、场景尺度、时间和渲染器 |
| 降雨接触 | 沿雨方向捕获第一层表面，驱动雨丝遮挡、水花落点；局部雨区由云场控制 | 将屋顶、地形、树冠等正确加入捕获；透明屋顶需显式指定遮雨规则 |
| 表面响应 | GPU 历史纹理累积湿润和积水，材质改变粗糙度、法线与反射 | 按石材、木材、土壤设置吸水和积水遮罩；当前小院主要沿用默认湿润参数 |
| 听觉与事件 | 本项目扩展声音：读取同一局部雨量与遮挡采样；雷声由闪电事件触发，并按距离延迟 | 相机位置、每米尺度、音频开关、暂停生命周期；更多素材和空间声学需另外实现 |
| 场景行为 | 本项目扩展树冠随风摆动、夜灯和窗口随时间亮起 | 灯具、植被、人物、设备的实际业务规则 |

## 当前入口具体展示了什么

打开本地 `/lab/` 的“听雨小院”。石径、屋檐、长椅、树木、花坛、院灯和远山由代码生成；上方五个按钮保留当前观察机位，只改变天气和时间。

| 切换 | 观察对象 | 说明 |
| --- | --- | --- |
| 晴天 | 天空、树影、石径 | 光照与云影共同变化；若刚停雨，地面仍可能湿润 |
| 降雨 | 屋檐、石径、花园 | 12 秒天气过渡后，局部雨量决定水迹累积；檐下雨声衰减且高频减少 |
| 雷暴 | 厚云、落雷、雷声 | 展开参数可测试闪电；仅雷声模式便于核对事件，不会无事件持续制造雷声 |
| 暮色 | 天空、窗口、院灯 | 太阳时间变化，暖色灯光逐渐亮起 |
| 夜晚 | 月光、云层、照明 | 同一院落在夜间的可见性和氛围；不是独立夜景素材 |

“观察主题”仍提供建筑、景观、材质三组机位配置。“实践记录”保留本次事件、声音状态和资源统计，可导出 JSON。

## 对白鹭河谷（003）的实际接入判断

当前 003 使用 Three.js r185 的 `WebGLRenderer`，含自定义 GLSL、`ShaderMaterial` 和 `onBeforeCompile`；004 使用带上游补丁的 r186 WebGPU / TSL。因此不能直接复制几个天气文件就得到同等效果。依据是本仓库的 [003 场景入口](../003-mountain-railway-diorama/app/scene.mjs)、[Three.js 版本](../003-mountain-railway-diorama/app/vendor/three.core.js) 及其场景材质源码；此判断只对应本次核查状态。

可分两条路线：

1. **先复用环境状态和声音联动。** 保留 003 现有渲染方式，将时间、雨量、风速、相机位置、遮挡和闪电事件整理成统一输入；复用声音控制、淡入淡出及录音。003 的画面继续使用自己的天气实现，不能宣称已经拥有 Eanpa 的体积云。
2. **需要同等云、雨与湿润效果时，再迁移渲染。** 先迁移一小块包含地形、桥和屋顶的代表区域；将水面、植被、季节与后处理中的自定义着色器迁移到兼容节点材质，统一尺度、相机和光照。通过画面与性能验证后再扩大场景。

第二个独立画布可以并排对照，但不能自动共享深度、遮雨和反射，不应视为已经完成同场景集成。本轮没有修改 003。

## 建议沉淀的接口与交付边界

下一步可将宿主适配抽成 `attach(scene, camera, renderer)`、`setEnvironment({hours, weather, wind})`、`update(dt)`、`dispose()`，另提供遮雨物体登记和落雷回调。这是建议接口，当前 `/lab/` 仍是可运行接入实例，不是已发布通用 SDK。

优先顺序：固定小院作为回归样例 → 提取适配层 → 增加材质分区和不同雨声素材 → 接入一个代表性外部场景 → 再建立设备档位与长期运行测试。先测云、反射和雨捕获各通道的 GPU 耗时，再决定降低哪一项预算；减小下载量不等于减少 GPU 计算。

## 不具备的物理能力

地面水迹是视觉历史场，没有径流、排水网络、困水体积和完整流体模拟；目前的声音是距离、滤波和增益近似，没有完整声线追踪、绕射及建筑混响。云场和天气预设也不提供气象预测。大场景中的有限捕获范围、强风高物体、屏外反射和首次着色器编译需要专门验证。

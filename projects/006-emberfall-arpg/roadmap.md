## 目标与范围

目标是形成一段有空间层次、探索选择、战斗变化和世界反馈的完整首章，期望首次游玩约 30–45 分钟。先交付一个可独立评估的 5–8 分钟样段，以真人结果决定是否扩展。

沿用单人、等距视角和本地保存。优先服务桌面键鼠，明确记录实际测试设备、浏览器与窗口尺寸。暂不增加联机、完整开放世界、多职业、随机地图、完整派系、云存档、赛季运营和商业化。现有三地区域作为回归基线保留。

## 阶段与顺序

| 顺序与优先级 | 要解决的问题 | 交付内容 | 进入下一阶段的条件 |
| :--- | :--- | :--- | :--- |
| S0 · P0：建立体验基线 | 规则已通，但不知道玩家实际卡在哪里 | 固定起点的一次完整手动游玩记录；相同机位截图；迷路、受击、死亡、遮挡、载入和操作问题清单 | 记录实际证据，排定阻碍游玩的前三项问题；不使用自动模拟耗时替代真人结果 |
| S1 · P0：可走通的场景样段 | 场景仍像平面功能区 | 营地出口、商道分叉、废弃哨站；一处可进入建筑、一条坡道或高差通路、一条回环捷径；同步碰撞与地图 | 全程可走通、可折返；画面与可通行范围一致；没有卡死与严重遮挡 |
| S2 · P0：可判断的战斗 | 需要验证操作和敌人组合是否有趣 | 在同一样段安排两组不同遭遇，调整攻击前摇、受击、闪避与追击；统一近战和远程反馈 | 玩家能识别威胁和失败原因；两组遭遇需要不同站位或优先级；正常资源下可通过 |
| S3 · P1：任务与世界反馈 | 清怪结束后世界变化太少 | 完成一次救援，让 NPC 返回营地并开放服务或情报；完成一条可解锁捷径 | 变化在画面、交互、导航和存档中一致；不能重复领唯一奖励；死亡和刷新不破坏状态 |
| S4 · P1：美术与声音样板 | 原型资产缺少统一完成度 | 对同一样段完成环境资产、材质、角色关键动画、环境音与战斗音；建立可复用规范 | 相同路线前后对照可评估；人物与威胁清楚可见；资源出处和许可有记录；在基线设备复测性能 |
| S5 · P1：形成两种打法 | 装备主要只改变数值 | 两组技能与装备组合、明确的获得路径和比较说明；相同遭遇的对照试玩 | 操作节奏或选择发生变化；玩家能解释取舍；掉落、穿戴、出售与存档通过回归 |
| S6 · P2：扩为完整首章 | 一小段体验能否推广到完整流程 | 将验收后的规则与资产用于野外和地下城；完善首领、返程与章节结算 | 多次从新档到通关的真人记录；无阻断流程问题；时长、难度和性能达到实测后确认的目标 |

可在 S1 时制作少量美术样板确定比例和光照；整段精修安排在主要通路与战斗稳定之后，减少布局变更导致的返工。只有 S6 之后再评估定向刷取、事件变化和更长的重复远征。

## 第一批具体任务：S0—S1

| 任务 | 输出 | 验收证据 |
| :--- | :--- | :--- |
| T01 · 固定复测条件 | 使用备份的新档／检查点，记录设备、浏览器、画质和尺寸 | 起点、输入方式、真实耗时和问题位置可复现；用户原进度可恢复 |
| T02 · 绘制样段布局 | 有主路、分叉、建筑入口、高差和返回路径的俯视设计图，注明每个地点的用途 | 每条路有用途，关键出口有地标，没有只有装饰意义的任务地点 |
| T03 · 拆分关卡数据 | 把地形高度、通路、实体障碍、入口、交互点和遭遇定义为共同数据 | 渲染、导航、小地图和交互引用相同定义；现有存档迁移有方案 |
| T04 · 搭建基础几何与镜头 | 用简化模型实现哨站室内外、坡道与回环；处理屋顶和前景遮挡 | 玩家不穿过实体建筑；门内外进出正常；人物在关键通路可见 |
| T05 · 小范围试玩 | 完成营地出发、抵达哨站、发现支路、返回营地 | 记录偏航、误点、寻路失败与镜头问题；优先修复影响通行的项 |

第一批结束时应交付：实际可走的样段、设计图、同机位截图、问题与修改记录、复测结果。暂不承诺已经达到 5–8 分钟或完整首章质量。

## 样段的玩家经历（待实现设计）

1. 在营地得到“商道失联”的清晰目标，看见远处哨站的地标。
2. 从城门走上商道，在分叉处选择正路或有风险的侧路。
3. 经过一次基础遭遇，认识敌人预警、闪避和回复手段。
4. 进入哨站建筑，通过室内路线或高差通路发现被困者与返回捷径。
5. 在第二次组合遭遇中使用已学会的操作，完成救援。
6. 开放回环返回营地，看到 NPC 迁入或新服务，获得与下一次出发有关的奖励。

S1 只要求空间与通路；战斗、救援和永久变化分别在 S2、S3 接入。不把六步描述当成已经做好的关卡。

## 实现约束与关键风险

### 共享空间数据

目前主要使用平面 x/z 导航。高差需要地面高度查询、层级或连接关系；角色高度、碰撞、寻路和交互距离必须一起处理。首个样段先验证坡道与室内外过渡，同一 x/z 上叠多层、攀爬和平衡暂不实现。发现现有方案无法稳定承载时，先比较方案再决定架构调整。

### 任务事件与世界状态

建议将“救援完成”“NPC 已迁入”“捷径已开放”“唯一奖励已领取”作为独立、可保存的状态，驱动场景、服务和导航变化。事件重复到达时只能产生一次结果。刷新、死亡、换图和旧档迁移都应覆盖，不能只改变对话文字。

### 资产与表现

先列出建筑、地表、道具、角色、动作、特效和音效清单，逐项记录来源、许可、状态与复用范围。优先补走／跑、攻击、受击、死亡和闪避关键动作；装备外观是否随穿戴改变单独记录。商业产品对标不授权复制其资产。

### 性能与技术选择

记录场景载入时间、稳定游玩帧时间和明显卡顿，而非只报瞬时 FPS。目标设备未明确前不承诺统一帧率。新样段使用同一设备与条件进行前后对照；若性能或功能持续不达标，再评估资产预算、场景分块与引擎方案。当前不确定迁移引擎。

## 试玩与验证计划

| 层面 | 检查内容 | 记录方式 |
| :--- | :--- | :--- |
| 规则回归 | 已有 20 项基线；新增高差通行、路线解锁、任务事件、唯一奖励与迁移测试 | 记录本轮实际执行数量和结果，不把计划测试计为通过 |
| 自动流程 | 正常输入从出发到回营；保留死亡／重试路径 | 说明模拟输入能力和局限，不代替真人体验 |
| 人工流程 | 新档、继续、死亡、换图、室内进出、捷径和结算 | 标出问题发生地点、复现方法、修复与复测状态 |
| 体验观察 | 是否理解目标、为何绕路、能否识别敌人、是否感到救援有结果 | 后续建议邀请 3–5 位首次体验者，记录观察与原话；尚未安排或完成 |
| 视觉与声音 | 同机位对照、人物辨识、遮挡、攻击与受击声音、环境层次 | 实际截图／录像和音效检查；概念图与实机图分开标注 |
| 性能 | 初次载入、关键战斗、区域切换和持续游玩 | 记录设备、浏览器、尺寸、画质、采样条件和结果 |

扩展门槛：只要仍有阻断通行、无法理解目标、攻击反馈不清或存档丢失，就优先修复相应阶段。一次自动通关不能替代这些检查。

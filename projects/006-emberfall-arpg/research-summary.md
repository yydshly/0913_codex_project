# 006 · 从游戏效果到交互与教学体验：研究总览

整理日期：2026-09-14。范围：本次对话及 006 项目的全部探索，不包含仓库其他项目的独立研究。[在线试玩 ARPG](https://yydshly.github.io/0913_codex_project/006-emberfall-arpg/) · [在线研究导览](https://yydshly.github.io/0913_codex_project/006-emberfall-arpg/research/)。本文是当前入口；旧文档中的“当前”“下一步”应按其所属阶段理解。

**我们的研究从暗黑风格 ARPG 的画面效果出发，逐步理解怎样让场景可玩、让操作产生反馈，再让反馈帮助使用者感受与理解规律。** 由此形成的方向是：以情绪价值为主要驱动，以交互价值为参考，将游戏的场景表现与实时反馈用于可探索、可比较、可解释的体验，进一步尝试物理等教学内容。

当前已实现浏览器 ARPG、三维教学工坊和二维杠杆实验台。杠杆实验室 0.1 是现阶段的具体样件，代表我们对“直接改变条件、看见结果”的一次实践；游戏、互动展示和教学体验仍是这些认识可以继续应用的方向。它们的产品效果需要分别验证，尚不能据此声称已有成熟通用框架或已证明教学有效。

**我们保留下来的理解有三层：**画面负责吸引与传达氛围；操作与世界反馈让场景产生用途；可重复、可比较的因果关系让体验有机会支持理解。每一层都需要实际使用来检验，增加地图或功能数量本身无法代替这种检验。

好奇、惊喜与掌控感是设计目标。下一步先观察使用者能否自主完成“改变条件 → 观察 → 比较 → 解释”，再决定要扩展游戏场景、物理现象还是教学内容。研究网页用于阅读与效果查看，杠杆实验台仍是本地 Windows 程序，尚未网络发布。

## 3. 当前实验台究竟能体验什么

使用者可以改变一个质量或移动一个位置，运行观察倾斜，保存为 A，再改变 B，以相同模拟时间比较两组装置与曲线。暂停、单步和慢放用于看清过程；回放读取已记录状态，不改写当前实验。

模型使用无自重刚梁、固定在梁上的两个质点、竖直重力、黏性阻尼和非弹性角度限位。力臂按支点到重力作用线的水平距离计算。模拟频率 120 Hz、记录频率 30 Hz，每次最多记录 12 秒模拟时间。它是简化教学模型，尚非通用刚体实验环境。

每次改变配置，B 从水平静止状态重新开始记录。A 保留当时的配置与记录；两者只在本次会话中保存，关闭即清空。当前没有实验文件导出、能量图、自由装配、摆动和碰撞模块。

Windows 包位于 `app/lever-lab/dist/LeverLab-win64-0.1.zip`，仅本地生成、不提交仓库、未网络发布。当前采用官方 Godot 编辑器运行时加载 PCK，EXE 约 156 MiB、窗口带 DEBUG 标识；精简正式导出与签名未完成。具体操作见 [实验台指南](app/lever-lab/README.md)。

## 4. 情绪价值如何落到产品判断

| 希望产生的感受 | 对应的体验设计 | 下一步观察的行为 |
| :--- | :--- | :--- |
| 好奇：我想试试 | 可以直接抓取重物与支点，改变一个条件就能看到变化 | 使用者是否主动开始操作、尝试第二种配置 |
| 惊喜：原来这样也可以 | 展示不同重量仍能平衡的可操作例子，并保留对比 | 是否能指出结果与原先预想的差别 |
| 掌控：我知道怎样改变结果 | 暂停、单步、慢放、恢复与 A/B 比较 | 是否能有目的地让装置向另一侧倾斜或接近平衡 |
| 理解：我能讲明白 | 围绕使用者刚刚做过的实验解释力臂和力矩 | 换一个布局后，是否仍能预测方向并说明原因 |

上表是待验证设计假设。操作次数、停留时间和测试通过都不能单独证明情绪或学习效果。当前不默认恢复角色任务、奖励关卡或长剧情；将来若引入，必须说明它们如何帮助目标体验。

## 8. 下一步如何驱动

1. **先完成一次真实使用观察。** 请首次使用者自行改变一个条件、观察、保存对比并解释差别。记录卡住的操作、看不懂的标记和主动尝试，暂不把教学有效性预设为结论。
2. **根据证据打磨这一个实验。** 优先解决拖动、单位、力臂辨识与对比理解的问题。年龄范围与使用场景尚未确认，应在课程内容扩张前确定；是否增加记录导出由实际使用需求决定。
3. **再决定第二种现象。** 摆动或碰撞是候选，不是已排期功能。选择标准是能否提供不同的可观察因果关系，并复用已有慢放、回放与对比方式。
4. **更后面再讨论自由装置创作。** 多部件组合、课程组织、教师工具和正式分发需要新的范围与验证，不将它们混入当前 0.1 的完成声明。

开发分阶段；使用者在每个已完成实验中自由探索。后续判断顺序为：目标感受 → 可观察行为 → 必要交互 → 模型与素材 → 真实验证。

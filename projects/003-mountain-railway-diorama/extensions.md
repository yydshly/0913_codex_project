# 003 · 扩展方向

[研究总览](README.md) · [源码笔记](notes.md)

以下是基于源码结构的设计建议，均尚未实施。工作量为相对判断，不是工期承诺。

| 方向 | 可利用基础 | 建议新增内容 | 工作量与难点 |
| :--- | :--- | :--- | :--- |
| 场景配置化 | 模块工厂、固定曲线与位置参数 | 提取轨道控制点、站点、建筑、天气预设 | 中；地形、铁路、镜头和植被的坐标规则相互关联 |
| 点击导览 | 三维对象、预设镜头 | 稳定对象 ID、射线拾取、信息面板、键盘等价入口 | 中；实例化对象识别、遮挡与小屏面板 |
| 四季和地方主题 | 植被变体、调色、环境状态 | 樱花、雪景、地方建筑和列车涂装 | 低至中；积雪和季节形态不能只靠换颜色 |
| 环境声音 | 列车位置、速度、驻站与雨量 | 轮轨、雨声、溪流与到站提示，按距离调节音量 | 中；音频授权、声音启用、混音和循环衔接 |
| 可视化编辑器 | 曲线与程序化几何 | 拖动铺轨、摆放建筑、撤销、保存和读取配置 | 高；重建成本、几何约束与数据版本 |
| 多车调度 | 单列车路径逻辑 | 分离路线与车辆状态，区间占用、信号、道岔和冲突处理 | 高；多创建一个车模型并不等于调度实现 |
| 游戏玩法 | 列车、场景、状态栏 | 任务、资源、乘客、输入、存档和反馈 | 高；核心规则需要新增 |
| 地理数据接入 | 高度场、线路曲线 | 坐标转换、真实地形采样、路线简化 | 高；数据精度、尺度、许可和生成流程 |
| 设备适配 | LOD、实例化、GPU 计时 | 手动画质档位、触屏测试、加载与降级策略 | 中至高；需真实低性能设备验证 |

## 建议优先开展的实验

### A. 保持默认效果的配置化

先抽取天气预设和一个建筑的位置，再处理轨道控制点。记录每个参数会影响哪些地形、净空和镜头规则。

建议验收：默认配置通过既有回归检查；新配置明确桥隧和站点约束；截图记录变更；旧配置下通过的测试不能直接证明任意线路正确。

### B. 三处点击导览

选择车站、桥梁、神社，为其提供高亮、介绍、镜头定位和关闭返回。内容与三维对象分离，验证场景是否能承载文旅信息。

建议验收：鼠标与键盘均能开关，触屏可用，说明面板不遮住整个场景，自动镜头和用户操作不抢控制权。

## 复用限制

- 植被避让、桥隧分段和镜头构图针对当前景观编写，移植时需整理空间规则。
- `onBeforeCompile` 及 `THREE.ShaderChunk` 修改依赖着色器内部片段，升级 Three.js 后需要复查编译和视觉结果。
- 水流、雨雾与列车控制面向视觉表达，不能直接用于洪水或铁路安全计算。
- 首次加载包含几何构建与 Shader 预编译，加载耗时和内存尚未专项测量。
- 再分发时需保留上游和随附依赖许可；本轮归档上游 MIT 原文，未额外进行素材权利审计。


## 水体优化路线（V7 用户反馈后的调整）

以下是下一步方向，不代表已经实现。优先保留用户认可的连续水流，不把岩石、粒子数量视为画质目标。

| 优先级 | 方向 | 具体效果与验收 |
| :--- | :--- | :--- |
| P1 | 连续水流精修 | 改善上游平水、加速跌落和入潭的速度层次；减少亮纹重复、边缘锯齿与反射闪烁，不增加挡水岩块。 |
| P1 | 模式内独立调节 | 分别调水流厚薄、白沫、水雾与水面粗糙度；同机位比较，提供恢复该模式默认值。 |
| P2 | 岩石与水流关系 | 先减少人为五等分感，再做局部绕流、背水区与尾流；石头应嵌入地形，不能仅遮住水带。 |
| P2 | 阶梯溪流与静水 | 在现有连续、缓流、岩间三种模式之外，增加浅层多级跌水和静水倒影；每种模式有明确的景观用途。 |
| P2 | 环境联动 | 雨量驱动水量与浑浊程度，风驱动表层波纹，季节改变水位、岸冰和岸边湿润范围。 |
| P3 | 整体画质统一 | 植被层次、河岸土石过渡、光照与色调一起调整，避免水体单独变精细而周围仍过于简化。 |

扩展入口：`app/scene-water-modes.mjs` 集中定义各模式的有效落差、坡段、分束、泡沫和飞沫参数；新模式仍需补充相应 UI 与必要的几何/材质逻辑、验证和开发记录。


### V8 进展与剩余方向

已实现分段速度、避免流速调节跳位，以及厚薄、白沫、水雾、倒影、水纹五项独立控制与单模式重置。水纹强度不等同材质粗糙度，厚薄也不是几何厚度。上述 P1 中的亮纹重复、边缘锯齿与反射闪烁仍需继续专项比较；不能将整个 P1 视为完成。后续可优先做参数预设保存与同机位对比，再改进河岸与水面接触、低重复水纹和远近景一致性。


### V9 进展与剩余方向

已推进浅水岸缘、湿润色、局部水纹、白沫生命周期和上游水下河床的反射剔除，开发记录可查看同机位修改前后截图。仍需根据用户观感继续评估水帘轮廓、岸线的地貌细节和反射尖角；尚未做真实折射或绕流。当前不将画质目标视为全部完成。下一步可先收集默认连续水流的观感反馈，再决定是否沿相同方向适配其他季节或转向植被整体风格。


### V10：从单场景走向可复用构图

新增层峦溪谷和疏林浅湾，保留原有河谷；用同一季节、光线和水流系统验证空间配置可复用。主场景用于打磨，差异场景用于检查效果能否迁移。下一步仍可改善树林体积、自然岸坡与跨场景近景构图。线路和建筑暂未配置化，不把两个预设宣传为任意场景创作器。具体组合规则与实景证据见开发记录 V10。


## V11 后的植被优化顺序

1. 近景叶簇与枝条：先减轻叶簇片面感和分叉折线，再决定是否引入精细资产；继续在两种景观四季中比较。
2. 远近细节分级：近处保留树枝与弯曲叶簇，远处使用简化冠体；先测设备帧耗与显存，再制定质量档位。
3. 林缘与地表衔接：减少灌草重复，按坡度、湿润程度组织矮草和裸地，验证冬季覆雪后仍自然。

以上为待实现方向。V11 完成的是程序化树冠体积与连续渐细枝形，以及现有四季、光线、风场的代表性检查。


## V12 后的近期顺序

已完成地表独立季节配色、区域混合与草丛同步。接下来先依据实景反馈确认草地色调，再建设现有车站周边的生活样板：候车空间、少量建筑与人物，以及列车停靠镜头。后续再细化近景地表纹理、叶簇与枝条，维持两种构图和四季兼容验证。以上新增站点内容尚未实现。


## V13 后的地表细化

已补充真实树位关联的林地色、贴地落叶与短草斑块。后续先依据近景观感处理草叶重复、陡坡过渡和叶片尺寸；草丛数量增加后，应先测设备帧耗，再决定远近简化策略。站点生活样板仍待推进，不以堆放装饰替代地表自然度检查。


## V14 后的全域完善

新增后坡与空地机位后，可以用主全景、山后、林间空地、河岸和水流五个机位共同发现遗漏。后续优先根据实景观感细化铁路陡切坡的造型、缓坡植物疏密和空地叙事；大幅增加资产前先评估细节分级与构建耗时。当前未实现真实侵蚀、地质层理或自动生态演化。


## V15 后的优先项

已实现铁路旁高地的连续切坡与贴坡露岩。下一轮先依据山后、正面和空地实景反馈确认轮廓，再处理路堤与河岸局部突变；随后围绕车站建立候车、休憩与观景的小范围生活场景。草叶重复、树冠近景、岩面形状和设备性能仍需单独优化；不把新增数量作为质量指标。


## V16 后的水石方向

先维护固体与水面缺口的一致性，再逐步增加可信的绕流、石后回流和落点白沫。若开放拖拽堆石，应新增堵塞率、上游蓄水、溢流高度与下游流量规则，不能直接复用当前静态遮挡来声称完整水动力模拟。铁路周边新增资产也应沿用完整体积的保护带检查。

## V17 后的水体优化边界

已补充水面自身纵向流动、小幅起伏和按水线定位的落点。下一步可优先研究落水池回旋与岸边回水，让下游流向受岸线约束；再扩展不同落差下的白沫形态与水雾尺度。需要水位上升、堵塞后绕路或溢流时，应另建水量与地形约束模型，当前纹理偏转不能代替这些能力。每轮继续保留零白沫/零水雾、暂停、三种模式和四季光线的代表对照。

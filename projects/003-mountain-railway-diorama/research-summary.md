# 白鹭河谷 · V38 阶段总结

2026-09-15 · 阶段研究完成，暂停主动迭代；后续由具体产品需求驱动。

## 我们最终理解了什么

这次研究从 Mountain Railway Diorama 的效果拆解开始，经过参数实验，再独立构建白鹭河谷。最终价值在于理解并验证：一个可体验的场景，需要空间布局、视觉风格、时间变化和对象行为共同工作。参数是创作入口，模块之间的约束与联系决定最终效果。

创作不能仅靠不断增加元素。岩石必须避开铁路，水中障碍需要影响可见流路，动物活动需要合理栖息地与连续转向，四季变化需要同时作用于植被、光线和活动。效果应以当前画面、使用场景与目标验收；开发记录用于追溯，不能替代实际观察。

## 技术如何驱动

本项目使用 Three.js 在浏览器中渲染实时三维微缩场景。地形与布局规则生成几何并决定对象位置，重复植被和痕迹等使用实例化减少绘制开销；材质与 Shader 表现水纹、叶片和风动。共享的季节、光照、风雨参数驱动多类对象，动画循环按时间推进列车与动物状态。

列车沿线路运行，停靠、开关门、上下客通过状态衔接；动物结合安全区域、路径与状态切换完成移动和停留。随机数提供变化，边界与转向约束使运动可理解。声音由本地 Web Audio 环境合成与 MiniMax 生成的两段到站/关门 MP3 组成，用户主动开启后播放，网页不持有生成服务的 API Key。

水流、积雪和行为是服务视觉体验的程序化近似，并非真实流体、气象或完整生态求解。参数调整也不等于自由建模，当前尚未提供任意摆放建筑、自由绘制铁路或从照片自动复刻现实地点。

## 当前已沉淀的能力

- 场景创作：三种构图、可调地形与布局、方案保存/恢复、导入导出及同机位比较。
- 四季环境：春夏秋冬、日夜光线、风与植被、雨天表现、初冬岸边薄冰；三种水流模式及精调。
- 车站生活：列车车头、玻璃开口与司机；候车室、值班室、门口连接；人物候车、行走、上下客与列车员巡视。
- 生态活动：白鹭飞离返回、野鸭游泳上岸、鱼群水下活动、睡莲与蜻蜓、季节花丛与蝴蝶，以及冬季兔子和落脚雪印。
- 展示与复用：在线研究、真实场景、开发记录、实景图、声音和历史归档，构成可回看、可演示、可继续开发的基础。

上述后期能力属于本研究独立实践，不代表上游原作原生提供了同样功能。

## 本次收尾新增了什么

本次整理沿用 V38 场景，不新增场景功能或改动画面算法。补充阶段理解、收尾原因、已实现能力与未实现边界；在原有引导图下加入当前线上 V38 的春季全景、冬季全景和兔子雪印实拍截图，附日期、参数与说明，并关联研究页、导览、源码说明与开发记录。

最新场景能力是 V38 的冬季兔子与落脚雪印，承接 V37 的叶簇分型与花形层次，以及此前的站房、人物、声音和动物。应区分“这次补充的说明与截图”和“此前已经实现的功能”。

## 为什么在这里暂停

现阶段已经达到研究理解与可体验展示的目标。继续围绕同一场景零散微调，新增价值有限，因此保留 V38 作为研究成果、展示样例与后续开发基础。暂停不等于所有质量问题已经消失，也不等于已经成为完整产品；未来只有明确使用者、目标场景和验收标准后再投入开发。

## 有实际产品需求时再开启的方向

| 产品或需求 | 可复用基础 | 届时需要补充的能力 |
| --- | --- | --- |
| 真实地点的风格化复刻 | 地形、植被、车房、光线和镜头 | 参考资料与比例标定、地标建模、道路/河道/铁路编辑、人工校正；当前不具备自动复刻 |
| 文旅或景点互动展示 | 四季场景、列车、人物与声音 | 游览路线、景点说明、导览镜头、真实内容与展示设备适配 |
| 可复用场景创作工具 | 参数与方案保存、三种构图 | 元素选择与摆放、撤销重做、素材库、地图/线路编辑及作品分享 |
| 有生活过程的互动场景 | 站房、乘客、列车员、上下客 | 室内寻路、候车落座到乘车的连续行动、任务与人物交互 |
| 四季生态与天气体验 | 动物栖息地、风雨、岸冰和雪印 | 狗及人物同行、觅食与避风、降雪覆盖足迹、连续温度驱动结冰等因果关系 |
| 正式公开使用 | 当前网页和部署流程 | 手机与长时间运行验收、性能预算、加载体验、声音听感、稳定性与可访问性 |

这些是可选择的研究方向，不是已排期的开发承诺。重启时先选一个具体场景，定义可观察的完成标准，再逐步扩展。

## 已知边界

人物尚未进入站房，乘车与司机动作仍简化；水流不能求解堵河后的蓄水溢流；兔子当前仅冬季展示，雪印约 75 秒淡去并非雪面形变；近景叶簇、枝干与岸壁仍有程序模型感。手机长时间运行与音频听感尚未完成专门验收。V36 为本机冻结包，V23 为公开历史归档，当前展示为 V38。

# 可运行历史版本

用户明确要求保存可操作的历史效果，因此本目录保留每个阶段的完整运行文件，作为研究档案；不是日常构建输出。

| 版本 | 内容 | 场景入口 | 文件与大小 |
| --- | --- | --- | --- |
| V001 | 本轮优化前的自然环境组合 | [打开](v001/app/outdoor.html) | 103 个文件，14,792,477 字节 |
| V002 | 树冠受光、透明边缘与地被调整 | [打开](v002/app/outdoor.html) | 110 个文件，15,102,194 字节 |

在项目本地服务运行时，从 [历史版本页](../app/versions.html) 打开。V001 曾以独立服务端口 4388 实际运行，不依赖开发版的文件。每个版本的 app/serve.mjs 也可单独运行；端口示例如已被占用，选择空闲端口。直接双击 HTML 不能代替 HTTP 模块服务。

## 封存逻辑

- 开发代码继续在 ../app/ 维护，旧版本不覆盖。
- 保存工具先建立新的临时目录，复制代码、依赖、素材及文档，写入回放设置与文件 SHA-256，校验后再作为正式目录。
- 原始场景配置不变，历史入口仅调整默认回放、历史标识和本机存档隔离；未应用草稿保留在 replay.json，默认不生成。
- 使用固定跟随/全景/动线/人物镜头作为回放入口，暂停后保存；任意自由镜头目前不会被保存工具接受。
- 每个 manifest.json 的 Git HEAD 仅供追溯，明确标记工作区包含未提交内容；真正的版本依据是归档文件本身。
- 禁止覆盖和篡改检测由保存/校验工具实现，不是操作系统只读锁。截图用于辅助比较，浏览器/显卡差异仍可能影响渲染。

## 后续保存与检查

在开发版 app 目录，先用页面状态工具记录暂停且 ready=true 的状态文件，然后运行：

```powershell
node snapshot.mjs create v003 ../assets/下一轮状态.json
node snapshot.mjs verify v001
node snapshot.mjs verify v002
node snapshot.mjs verify v003
```

随后在浏览器独立打开新版本，确认初始方案、机位、播放和素材加载；把实际结果追加到 ../effect-log.md，更新本目录 index.json 和开发版 versions.html。没有截图/验证的版本不能写成已验收。若有 .vNNN-pending，先调查失败原因，不覆盖或合并到既有版本。

新建版本前应再运行当前测试与构建检查。后续网页构建会复制封存目录，实际内容仍以开发区之外的本目录为源。

# 后续开发：火柴人游戏效果与 Skill

[![六组火柴人游戏效果的实际画面](assets/14-capabilities-overview.jpg)](reusable-capabilities.md)

**目标：把火柴人游戏效果和制作流程沉淀为 Skill，由 Codex 等代理驱动，制作这类游戏效果视频，或构建同类风格的游戏。** 当前已有可运行的效果与对战样例，人物刻画、故事时间轴和 MiniMax 配音是扩展实验；MP4 导出、通用游戏构建流程与 Skill 均尚待开发。

[当前能力](capabilities.md) · [效果导览](README.md)

## 两类交付物

| 扩展方向 | 示例作品 | 制作重点 |
| :--- | :--- | :--- |
| 火柴人游戏效果视频 | 动作展示、战斗短片、武器效果、碰撞与攀爬演示、玩法介绍 | 调用已有角色与效果，编排场景和镜头，记录或重放物理结果，合成字幕/声音并输出 MP4 |
| 同类火柴人风格游戏 | 对战、攀爬、道具交互等具体玩法 | 复用形象、关节和物理反馈，添加操作、规则与关卡，交付可玩的游戏与可修改工程 |

Skill 将保存两类制作任务的复用方法和执行入口。它本身不会补齐缺失的渲染、视频编码或游戏机制；应先开发并验证这些能力，再把可重复的流程封装进去。

## 分阶段开发与验收

| 阶段 | 需要开发 | 交付与验收标准 |
| :--- | :--- | :--- |
| 1. 整理效果模块 | 火柴人外形、动作、关节、受力、握持、攀爬、场景与镜头接口；明确输入、反馈、参数和资源引用 | 独立样例可调用效果；新场景复用同一模块；无效配置有明确错误 |
| 2. 完成首支游戏效果视频 | 效果与镜头编排、画幅设置、物理状态记录/重放、固定帧率渲染、MiniMax 配音及 MP4 合成 | 成片能播放，动作/碰撞、镜头、字幕、声音和时长符合工程设置；不把无法回溯的实时模拟当作已有时间轴 |
| 3. 验证视频复用与修改 | 第二组动作或道具组合；局部镜头修改；配音与渲染缓存 | 不复制渲染器即可制作第二支视频；修改指定片段并保留未改内容；缓存不误用旧配置 |
| 4. 构建一个同类风格游戏 | 分离原对战规则，复用角色和至少一项物理机制，增加新目标、关卡与反馈 | 交付可玩版本与源码；操作真实改变游戏状态；验证规则和物理反馈，而不以预设播放代替玩法 |
| 5. 沉淀制作 Skill | 效果目录、模板、执行入口、依赖检查、预览、修改和验收流程；区分视频与游戏输出 | 在新任务中按需求调用已有能力，交付 MP4 或可玩游戏工程；失败时报告具体阶段，不伪造完成 |

画面验收应检查人物和道具接触、穿模、镜头遮挡、字幕安全区、音画对齐；游戏还要验证输入、碰撞结果、重置和胜负/目标条件。复用效率与成本收益需要实测。

## Skill 应保存什么

| 内容 | 约定与材料 |
| :--- | :--- |
| 输入 | 交付类型（视频/游戏）、希望展示的效果、角色与道具、场景、时长与画幅或玩法规则 |
| 风格与资源 | 火柴人造型规范、关节表现、材质配色、效果目录、素材来源和可用范围 |
| 编排与构建方法 | 将效果要求映射到动作、物理参数、场景与镜头；游戏分支配置操作、事件、规则和目标 |
| 可执行材料 | 视频工程和游戏工程模板、配音、录制/重放、渲染导出、运行与验证脚本 |
| 修改方式 | 保留未变角色、效果与镜头，局部调整动作/配音；游戏可独立修改规则与关卡 |
| 输出与验收 | 视频分支交付 MP4、字幕、预览和工程；游戏分支交付可玩版本、源码、运行说明与验证记录 |
| 错误与凭据 | 定位缺资源、物理重放不一致、配音或导出失败；密钥只通过本地配置提供，不写入工程、Skill 或浏览器 |

拟定分工：Codex 理解需求并调用工具；Skill 保存效果复用方法与流程；项目程序执行物理模拟、渲染、导出和游戏运行。以下为计划目录，当前尚未创建：

```text
stick-figure-effects/
├── SKILL.md           # 使用范围，视频/游戏两种交付路径
├── references/        # 风格、效果参数、编排与验收规则
├── assets/            # 效果目录、视频和游戏工程模板
└── scripts/           # 调用配音、录制、渲染、构建与验证工具
```

## 目标任务示例

- 视频：“用这种火柴人效果做一个 30 秒武器展示视频，依次展示挥剑、碰撞、失衡和起身，加入镜头切换与 MiniMax 解说。”交付视频及可修改工程；之后应能只修改最后一个镜头并重新导出。
- 游戏：“复用这种火柴人风格和攀爬效果，做一个可操作的攀爬小游戏。”交付可玩版本与源码，验证移动、抓边、攀回、失败重置和到达目标。

上述任务是后续开发的验收目标，当前不宣称已能通过 Skill 自动完成。现有生活故事提供编排与声音参考，仍可作为实验保留。

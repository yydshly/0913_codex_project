# 后续开发与创作 Skill 路线

[![三个已实现的生活故事，点击查看现有叙事基础](assets/20-story-overview.jpg)](stories.md)

**目标：让固定人物持续出演不同作品，并由 Codex 等代理驱动可重复的制作流程。** 本文是后续开发规划；当前尚无 MP4 导出、自动成片或创作 Skill。[当前能力](capabilities.md) · [效果导览](README.md)

## 两条扩展路线

| 方向 | 驱动方式 | 示例作品 | 需要保留的创作控制 |
| :--- | :--- | :--- | :--- |
| 叙事视频 | 剧本、分镜与时间轴 | 人物系列、家庭短剧、剧情片头、角色介绍、沟通情境教学 | 人物连续性、镜头节奏、表演细节、对白和声音 |
| 游戏效果与交互展示 | 玩家输入、事件与状态 | 角色操作、碰撞/攀爬演示、玩法教学、互动剧情、小型游戏原型 | 操作反馈、规则、触发条件、胜负或情境结果 |

优先打通视频制作闭环，交互分支根据实际作品需求迭代；不预先扩展成通用编辑器。

## 分阶段开发与验收

| 阶段 | 需要开发 | 交付与验收标准 |
| :--- | :--- | :--- |
| 1. 统一内容接口 | 分离人物、场景、道具、动作、镜头、对白与字幕数据；明确版本和资源引用 | 同一人物配置在两个不同故事中复用；旧演示继续可用；无效角色或动作引用给出可理解的错误 |
| 2. 打通第一支视频 | 横竖画幅、镜头切换、固定帧率渲染、MiniMax 配音与字幕合成、MP4 输出 | 先用一支已知故事完成端到端导出；成片可正常播放，画幅、时长、声音和字幕符合工程设置，人物不出画，镜头切换无漏帧 |
| 3. 用第二支故事验证复用 | 换情节与人物组合，支持只修改指定镜头/台词，复用未变资源与配音缓存 | 交付第二个不同故事的视频与可编辑工程；不复制一份渲染器；确认缓存不会误用旧台词、音色或镜头 |
| 4. 封装创作 Skill | 写入真实制作方法、模板、脚本入口、依赖检查、预览与验收流程 | 在新任务中，从自然语言需求生成可审阅工程、预览与视频；能按反馈修改；遇到缺依赖、配音失败或导出失败时明确报告，不伪造完成 |
| 5. 扩展交互路线 | 从对战样例分离规则，整理角色输入、物理接触和交互事件，按具体需求增加玩法 | 在一个新交互场景中复用角色及至少一项已有机制；操作真正改变状态，有明确反馈；不以播放预设动画冒充物理交互 |

视频验收还应检查手/道具接触、穿模、字幕安全区域、跨镜头人物一致性和音画对齐。观众能否理解情绪需要实际观看反馈，不能只靠程序测试判断。

## Skill 应沉淀什么

| 内容 | 本项目需要记录的规则与材料 |
| :--- | :--- |
| 输入约定 | 故事目标、人物关系、时长、横竖画幅、对白程度、音色和交付要求；缺省值明确记录 |
| 人物连续性 | 固定人物 ID、外形、声音、行为习惯；允许哪些变化，哪些应跨集保持 |
| 剧本与表演方法 | 将情绪拆成可见动作：停顿、视线、距离、伸手与回应；把剧本转成分镜和动作安排 |
| 可执行材料 | 故事工程模板、资源目录、配音生成、渲染导出与校验入口；使用项目相对路径或显式配置 |
| 质量检查 | 人物是否被遮挡/出画，字幕是否遮脸，接触是否合理，声音是否正常，输出时长与画幅是否正确 |
| 修改与失败处理 | 保留不变角色与镜头；仅重生成受影响内容；配音、资源和导出错误能定位并恢复 |
| 输出约定 | 可审阅剧本/分镜、可再次修改的故事工程、预览、MP4、字幕及素材/配音来源记录 |

拟采用的职责分工：**Codex 负责理解需求、安排工作与执行工具；Skill 保存制作流程和标准；动画底座负责实际计算、渲染与导出。** Skill 不会自动补齐缺失的引擎功能，也不应依赖代理每次重写底层代码。

建议在第 3 阶段验证完成后，再落地以下目录；现在不创建只有提示词、没有可执行链路的空壳：

```text
character-story-video/
├── SKILL.md           # 使用范围、输入输出、制作与验收流程
├── references/        # 人物连续性、分镜与表演规范、能力边界
├── assets/            # 工程模板、角色清单与经许可的示例资源
└── scripts/           # 调用已验证的配音、渲染和导出工具
```

官方将 Skill 定义为可组合说明、资源与可选脚本的复用工作流；跨环境使用仍需满足本项目的渲染、视频编码和 MiniMax 依赖。[OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)。凭据通过本地环境提供，不写入 Skill、故事工程或浏览器。

## 首个 Skill 的验收示例

输入示例：“用周岚与成年女儿制作一个 60 秒竖屏短片，表现想关心又怕打扰，少对白，使用 MiniMax 配音。”这是目标任务，当前没有宣称已能自动执行。

完成的标准是：可审阅的故事与分镜、符合既有人设的表演、可播放的视频，以及能再次修改的工程。再提出“只延长最后一个停顿、保留其余内容”，应能基于已有工程修改并重新导出。这种完整制作与修改经过实际验证后，才将该 Skill 标为可用。
